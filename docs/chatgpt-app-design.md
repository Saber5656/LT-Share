# ChatGPT内 LT Share 試作

2026-10-18。依頼「一旦ChatGPT内アプリとして構築してみて」に基づく構成変更。

Product Design 0.1.56 の user-context preflight（保存済みcontextあり）、image-to-code を実行。選定済み `design/concepts/post-preview-form-revised.png` を継承し、ChatGPTのインライン画面に合わせる。スマホの枠を描かず、白/黒、細い区切り、18px余白、4段階の入力フォームを維持する。画像素材は利用者が選択する実写真のみ。装飾画像は不要。

1. ハッシュタグ（複数）
2. 写真を選ぶ／撮影 → 本人のChatGPTに要約を依頼
3. 約100文字の投稿文（編集可能）
4. 開発者を含める（初期OFF）→ 全文確認・Xリンク・コピー

ヘッダーに「次の投稿へ」。履歴は同じウィジェットの状態として保持し、独自DBを設けない。会話/ウィジェットをまたぐ完全な履歴復元は保証しない。必要な本文はコピー/下書きファイルで退避できる。

写真は公式 uploadFile と imageIds によりモデルに渡す。MCP Apps bridge の ui/message により利用者の会話でモデルが要約し、render_lt_post に確定本文を渡す。サーバーは表示処理のみで推論APIを呼ばない。使用モデル・使用上限はChatGPT側に従い、アプリが軽量モデルや使用量を保証しない。

SitesのステートレスMCP接続口を使用する（元のバックエンド全面禁止から、今回明示されたChatGPTアプリ試作に必要な接続口を追加）。サーバーDB、秘密APIキー、独自認証、メディア保管は追加しない。既存Sites版と別の本人限定Siteとして配布する。

空/待機/アップロード失敗/生成依頼の送信失敗/生成結果待ち/手入力済みを区別。タイマーで生成済みにしない。遅延した結果はdraftId・requestIdで対応し、手入力は上書きしない。ホスト不在なら生成依頼不可と表示。ホストに写真APIがなければ会話の添付を使う案内。

写真アプリへの自動保存・動画音声要約・Xネイティブアプリの直接起動は、このiframe方式で達成済みとは扱わない。ChatGPT内の画像送信・モデル実行は実ホストで別途確認する。

アクセシビリティ: 可視ラベル、44pxの操作領域、キーボードフォーカス、aria-liveエラー/状態表示、狭幅で折り返し。テーマはホスト背景に合わせた明暗対応。
